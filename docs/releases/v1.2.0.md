# KAOS 1.2.0

## Status

`1.2.0` is the cumulative local-persistence release of KAOS. Its annotated Git
tag is `v1.2.0`, and its GitHub Release publishes the versioned JAR, TAR, and ZIP
produced from verified merged `main`.

This checkpoint represents every verified capability from the evolutionary
reset through completed Local Persistence Epic 004. It is not a claim of
production readiness, a stable public library API, indefinite database
compatibility, or completion of the broader KAOS vision.

## Included evolutionary foundation

- one-goal-at-a-time development rooted at roadmap #814;
- one root Gradle/Java 21 application and one production entry point;
- package-first evolution with evidence gates before modules, repositories, or
  services;
- validated local configuration, safe coded diagnostics, deterministic tests,
  packaging, and the `verifyLocal` checkpoint; and
- the evidence-based living architecture and technical flow maps.

## Included local AI and conversation capability

- fixed-loopback Ollama reachability and one explicitly selected local model;
- bounded prompt construction, context window, response generation, UTF-8
  streamed NDJSON, hidden reasoning, deadlines, cancellation, and clean
  completion validation;
- selectable foreground conversations with isolated ordered user and assistant
  histories;
- fixed limits of eight loaded conversations, 32 clean turns per conversation,
  and 65,536 Unicode code points per stored message; and
- deterministic real-client loopback tests for streaming, failure isolation,
  selected context, and conversation behavior.

## Included local persistence

- SQLite selected as the local authoritative conversation store;
- schema version 1 with validated conversations, ordered messages, foreign key,
  and read index;
- one fixed `conversations.db` filename under a configurable local data
  directory;
- transactional conversation creation and atomic user/assistant pair writes;
- restart restoration of the newest bounded foreground working set while the
  durable collection may grow beyond that set;
- identifier allocation above the complete durable collection;
- classified locked, corrupt, read-only, capacity, unavailable, invalid-state,
  and unknown persistence failures;
- phase-specific privacy-safe recovery with no automatic lock wait, retry,
  repair, replacement, or deletion; and
- restart-spanning application-to-real-client-to-loopback-provider-to-SQLite
  integration evidence, including exclusion of failed partial turns.

## Run and verify

From the repository root with Java 21:

```powershell
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
```

Run the persistent conversation command with an installed local model:

```powershell
$env:KAOS_OLLAMA_MODEL = "qwen3:4b-instruct"
$env:KAOS_OLLAMA_THINKING = "off"
./gradlew.bat run --args=conversation
```

The release build produces `KAOS-1.2.0.jar`, `KAOS-1.2.0.tar`, and
`KAOS-1.2.0.zip` under `build/libs` and `build/distributions`.

## Security, privacy, and data ownership

- AI traffic remains fixed to Ollama on `127.0.0.1:11434`.
- Persistent conversations contain exact local prompt and answer content.
- The default database is `.kaos/conversations.db` below the Java user-home
  directory; filesystem access to that directory controls local privacy.
- Storage and AI diagnostics exclude database paths, SQL, driver details,
  prompts, answers, provider bodies, reasoning, and stack traces.
- Corrupt or inconsistent storage is preserved; operators are directed to stop
  KAOS and make an offline copy before deliberate diagnosis or repair.
- No credential store, remote provider, telemetry service, background worker,
  event bus, plugin system, or separate runtime service is introduced.

## Compatibility and limitations

Schema version 1 is the current verified format. KAOS validates it on startup
and rejects unsupported or inconsistent state, but `1.2.0` does not promise a
permanent migration or backward-compatibility policy for future schemas.

The CLI restores only the newest eight conversations and deterministically
selects the newest restored conversation. It does not yet provide paging, exact
last-selection persistence, naming, deletion, trimming, summarization,
automatic rollover, provider-token estimation, automatic retry, or automatic
database repair.

## Roadmap checkpoint

This release snapshots completed Epics 000-004 and all seven Local Persistence
features, ending with Feature
[#864](https://github.com/karanbabu2110/KAOS/issues/864). First Knowledge and RAG
Capability Epic [#11](https://github.com/karanbabu2110/KAOS/issues/11) and its
first Feature [#865](https://github.com/karanbabu2110/KAOS/issues/865) are next
approved but not included or active in this release.

Rollback is selecting the preceding immutable `v1.1.0` tag. A rollback does not
convert or remove an existing schema-version-1 database; preserve local data
before switching application versions.

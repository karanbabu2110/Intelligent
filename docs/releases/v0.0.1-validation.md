# KAOS 0.0.1 validation and publication checkpoint

## Outcome

Feature [#839](https://github.com/karanbabu2110/KAOS/issues/839)
delivers one explicit result: the minimal KAOS Java application is versioned,
verified, and published as the `v0.0.1` initial-development baseline.

The version does not add a product capability. It gives the known working
starting point a stable Git identity before application configuration and later
AI behavior are introduced.

## Application contract

- **Input:** none. Arguments are currently ignored and no configuration,
  environment variable, file, credential, or external service is read.
- **Output:** one exact local diagnostic: `KAOS application baseline is
  running.`
- **State:** none is created, modified, or persisted.
- **Lifecycle:** `main` prints the diagnostic and returns normally; there is no
  background thread or resource to cancel or recover.
- **Ownership:** the root Gradle project and `io.kaos.app` package own the
  application entry point.
- **Failure:** compilation or test errors produce a non-zero Gradle failure;
  unexpected runtime exceptions remain visible rather than being swallowed.

Invalid-input, unavailable-dependency, permission, cancellation, and recovery
paths are not fabricated because the current application accepts no input and
uses no fallible dependency or persistent state. The feature that introduces
each surface must add and verify its corresponding behavior.

## Reproducible validation

Run from the repository root with Java 21:

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat test --tests io.kaos.app.KaosApplicationTest --no-daemon
./gradlew.bat clean test build check --no-daemon --warning-mode=all
./gradlew.bat run --no-daemon
Get-ChildItem build/libs,build/distributions -File
git diff --check
```

Expected and observed results before publication:

| Check | Result |
| --- | --- |
| Gradle properties | `version: 0.0.1` |
| Focused tests | 2 passed, 0 failed/errors/skipped |
| Clean build/check | Passed; eight Gradle tasks executed |
| Application run | Exact baseline diagnostic and normal exit |
| Artifacts | JAR, TAR, and ZIP names all contain `0.0.1` |
| Production dependencies | None |
| Documentation links | All repository-relative Markdown links resolve |
| Diff | `git diff --check` passes |

After merge, the same clean build and run are repeated on the tagged main
commit before the release is published.

## Release procedure

1. Merge the one Feature 001.01 pull request.
2. Fast-forward local `main` and rerun the clean build, test, startup, and
   artifact checks.
3. Create annotated tag `v0.0.1` at that exact main commit and push the tag.
4. Create GitHub pre-release `KAOS 0.0.1` using
   [the release notes](v0.0.1.md).
5. Attach the versioned ZIP distribution produced from the tagged commit.
6. Verify the tag target, release metadata and asset, issue/project state, and
   deleted feature branch.

## Limitations and next checkpoint

`0.0.1` has no stable public API, persistent-data schema, plugin contract, or
compatibility guarantee. It is not an AI release and does not require a
migration from earlier unversioned commits.

After publication, Feature
[#840](https://github.com/karanbabu2110/KAOS/issues/840), Application
Configuration, is the one approved next goal. No Feature #840 implementation is
included in `0.0.1`.

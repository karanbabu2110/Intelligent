release identity. It adds the first complete local Knowledge and RAG path to the
evolutionary foundation, local AI, conversations, and local persistence already
checkpointed by `v1.2.0`.

## Reproducible validation

Run from the repository root with Java 21:

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
Get-ChildItem build/libs,build/distributions -File
Get-FileHash build/libs/KAOS-1.3.0.jar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.3.0.tar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.3.0.zip -Algorithm SHA256
git diff --check
```

Release preparation must verify:

- Gradle reports version `1.3.0`;
- all expected tests pass with zero failures or errors and only documented skips;
- all 11 `verifyLocal` tasks execute successfully;
- `KAOS-1.3.0.jar`, `KAOS-1.3.0.tar`, and `KAOS-1.3.0.zip` are rebuilt;
- changed repository-relative release and architecture links resolve;
- the architecture status matches completed Epic 005; and
- `git diff --check` passes.

## Publication procedure

1. Review and merge the `1.3.0` release checkpoint pull request.
2. Fast-forward local `main` to the exact merge commit.
3. Confirm merged `main` has the same tree as the validated preparation head.
4. Reuse the validation only when those trees are identical; otherwise rerun it.
5. Create annotated tag `v1.3.0` with annotation
   `KAOS 1.3.0 - Knowledge and RAG` at that verified `main` commit.
6. Push only the `v1.3.0` tag.
7. Create the GitHub Release from that tag using the reviewed release notes.
8. Upload `KAOS-1.3.0.jar`, `KAOS-1.3.0.tar`, and `KAOS-1.3.0.zip`.
9. Verify local and remote tag targets, annotation, release assets and hashes,
   release metadata, and clean repository state.

## Limitations and next checkpoint

The version identifies the complete First Knowledge and RAG capability
baseline; it does not claim production readiness, verified model claims,
general document support, a public library API, permanent SQLite compatibility,
remote providers, or distributed operation.

Completed Epics 000-005 remain immutable release evidence. Epic 006 — First
Memory Capability is next approved but remains in Backlog and is not included or
active in `1.3.0`.

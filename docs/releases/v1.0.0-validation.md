# KAOS 1.0.0 validation and tag checkpoint

## Outcome

`1.0.0` gives all verified work through completed Epic 002 one cumulative
release identity. It includes the evolutionary foundation, minimal application,
and complete first local AI integration rather than only Feature 002.07 or PR
#25.

## Reproducible validation

Run from the repository root with Java 21:

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
Get-ChildItem build/libs,build/distributions -File
git diff --check
```

Release preparation must verify:

- Gradle reports version `1.0.0`;
- all 114 tests pass with no failures, errors, or skips;
- all 11 `verifyLocal` tasks execute successfully;
- `KAOS-1.0.0.jar`, `KAOS-1.0.0.tar`, and `KAOS-1.0.0.zip` are rebuilt;
- repository-relative documentation and architecture links resolve;
- the architecture page renders at desktop and mobile widths without page
  overflow or console warnings;
- `git diff --check` passes.

## Tag procedure

1. Review and merge the `1.0.0` release checkpoint pull request.
2. Fast-forward local `main` to the exact merge commit.
3. Rerun complete validation and inspect the versioned artifacts.
4. Create annotated tag `v1.0.0` with annotation `KAOS 1.0.0` at that verified
   `main` commit.
5. Push only the `v1.0.0` tag.
6. Verify local and remote tag targets, annotation, clean repository state, and
   absence of an unintended GitHub Release.

## Limitations and next checkpoint

The version identifies the first complete local-AI capability baseline; it does
not claim production readiness, a public library API, persistent-data
compatibility, remote providers, or distributed operation.

Completed Epics 000-002 remain immutable release evidence. Conversation
Capability Epic [#9](https://github.com/karanbabu2110/KAOS/issues/9) is active,
starting with Conversation Domain Model Feature
[#852](https://github.com/karanbabu2110/KAOS/issues/852). No conversation work is
included in `1.0.0`.

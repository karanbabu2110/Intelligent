# KAOS 1.4.0 validation and publication checkpoint

## Outcome

`1.4.0` gives all verified work through completed Epic 006 one cumulative
release identity and adds the first explicit, durable, inspectable, editable,
deletable, privacy-visible memory used by one bounded local AI path.

## Reproducible validation

Run from the repository root with Java 21:

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
Get-ChildItem build/libs,build/distributions -File
Get-FileHash build/libs/KAOS-1.4.0.jar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.4.0.tar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.4.0.zip -Algorithm SHA256
git diff --check
```

Release preparation verifies:

- Gradle reports version `1.4.0`;
- all tests pass with zero failures or errors and only documented skips;
- all 11 `verifyLocal` tasks execute successfully;
- all three versioned artifacts are rebuilt;
- changed local documentation and architecture links resolve;
- architecture and roadmap text match completed Epic 006; and
- `git diff --check` passes.

## Publication procedure

1. Review and merge the `1.4.0` release checkpoint pull request.
2. Fast-forward local `main` to the exact merge commit.
3. Confirm merged `main` has the same tree as the validated preparation head.
4. Reuse validation only when those trees are identical; otherwise rerun it.
5. Create annotated tag `v1.4.0` with annotation
   `KAOS 1.4.0 - First Memory Capability` at verified merged `main`.
6. Push only the `v1.4.0` tag.
7. Create the GitHub Release from that tag using the reviewed release notes.
8. Upload `KAOS-1.4.0.jar`, `KAOS-1.4.0.tar`, and `KAOS-1.4.0.zip`.
9. Verify local and remote tag targets, annotation, release assets and hashes,
   milestone closure, release metadata, branch cleanup, and clean status.

## Limitations and next checkpoint

This version identifies the complete First Memory Capability baseline; it does
not claim general-purpose memory, automatic inference, encryption, permanent
schema compatibility, remote synchronization, subjective model compliance,
production readiness, or distributed operation.

Completed Epics 000–006 become immutable release evidence. Epic 007 — First Tool
Integration is next but remains inactive until the user continues.

# KAOS 0.0.1

## Status

`0.0.1` is the first versioned KAOS application baseline. The Git tag is
`v0.0.1`, and the GitHub release is marked as a pre-release because KAOS remains
in initial development.

This version is useful as a reproducible starting point. It is not a claim of
production readiness or completed AI functionality.

## Included

- one Java 21 application in the root Gradle project;
- one production entry point: `io.kaos.app.KaosApplication`;
- deterministic startup output and normal process exit;
- two focused tests covering the baseline message and real `main` invocation;
- no production runtime dependency, external service, credential, persistent
  state, or required runtime configuration;
- the #814 evolutionary roadmap, one-goal workflow, package-first boundary
  rules, and proportional quality and safety guardrails.

The application currently prints:

```text
KAOS application baseline is running.
```

## Run and verify

From the repository root with Java 21:

```powershell
./gradlew.bat test --no-daemon
./gradlew.bat clean build check --no-daemon --warning-mode=all
./gradlew.bat run --no-daemon
```

The build produces versioned artifacts under `build/libs` and
`build/distributions`.

## Not included

- AI provider or model integration;
- command-line conversation behavior;
- application configuration or secret loading;
- persistence, knowledge/RAG, memory, agents, tools, browser or desktop
  automation, developer assistance, or a user interface;
- production deployment, compatibility guarantees, worldwide scale, or
  enterprise operational controls.

These remain ordered roadmap outcomes and are not hidden prerequisites for this
baseline.

## Compatibility and data

There is no public API, saved-data schema, plugin contract, or independently
consumed library in `0.0.1`. No migration is required. Until a real consumer or
persistent format exists, pre-1.0 releases may change without backward-
compatibility guarantees; each release must document any newly introduced
contract or migration need.

## Safety and rollback

The application performs no network, filesystem, credential, personal-data,
destructive, or external action. It starts, prints one local diagnostic, and
returns. Rollback is selecting the preceding Git commit; release verification
records the exact `v0.0.1` tag target.

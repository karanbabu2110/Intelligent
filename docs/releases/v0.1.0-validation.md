# KAOS 0.1.0 validation and publication checkpoint

## Outcome

`0.1.0` gives the currently verified local-AI application a stable minor-version
identity after Features 002.01-002.03 and the evidence-driven Feature 002.02
optimization follow-up were merged.

## Version identity

| Surface | Value |
| --- | --- |
| Gradle project version | `0.1.0` |
| Git tag | `v0.1.0` |
| GitHub release title | `KAOS 0.1.0` |
| GitHub classification | Pre-release |
| JAR | `KAOS-0.1.0.jar` |
| Distribution archives | `KAOS-0.1.0.tar`, `KAOS-0.1.0.zip` |
| Release notes | [KAOS 0.1.0](v0.1.0.md) |

The annotated tag must point to the verified release commit on `main`, never to
the preparation branch. Publication evidence is added after the release branch
is merged.

## Capability snapshot

| Surface | Verified `0.1.0` contract |
| --- | --- |
| Application | One root Gradle/Java 21 process and one production entry point |
| Commands | `status`, `help`, `ollama-status`, `ollama-model`, and one quoted `ollama-prompt` |
| AI boundary | Fixed local Ollama loopback endpoints only |
| Configuration | Explicit model; bounded context, thinking mode, and generated-token selection |
| Prompt lifecycle | One bounded non-streamed request and one validated complete answer |
| Failure boundary | Safe coded diagnostics; prompt/provider/exception details suppressed |
| State | No conversation, memory, knowledge, file, credential, or user-data persistence |
| Runtime dependency | Jackson Databind `2.22.1` for the real JSON protocol boundary |
| Architecture | One application with in-process `io.kaos.app` and `io.kaos.ai.ollama` packages |

## Reproducible validation

Run from the repository root with Java 21:

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
Get-ChildItem build/libs,build/distributions -File
git diff --check
```

Observed release-preparation results on 2026-08-28:

| Check | Observed result |

| Tests | 97 passed; no failures, errors, or skips |
| Artifacts | `KAOS-0.1.0.jar`, `KAOS-0.1.0.tar`, and `KAOS-0.1.0.zip` produced |
| Documentation links | All repository-relative Markdown and architecture links resolved |

The same checks are rerun from the merged `main` release commit before the tag
and GitHub release are published.

## Release procedure

1. Review and merge the `0.1.0` release checkpoint pull request.
2. Fast-forward local `main` to that exact merge.
3. Run the complete validation and inspect the versioned artifacts again.
4. Create annotated tag `v0.1.0` at the verified `main` commit and push it.
5. Create GitHub pre-release `KAOS 0.1.0` from
   [the release notes](v0.1.0.md).
6. Attach `build/distributions/KAOS-0.1.0.zip` built from the tagged commit.
7. Verify the tag target, release metadata, asset, and clean repository state.

## Limitations and next checkpoint

This release has no stable public API, durable data, plugin contract, remote
provider, streaming response, automatic retry, or production deployment
guarantee. It does not claim completion of Epic 002.

After publication, activate Response Streaming Feature
[#848](https://github.com/karanbabu2110/KAOS/issues/848). No Feature 002.04
implementation is included in `0.1.0`.

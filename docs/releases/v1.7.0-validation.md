## Reproducible validation

```powershell
./gradlew.bat properties --console=plain --no-daemon
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all --console=plain
Get-ChildItem build/libs,build/distributions -File
Get-FileHash build/libs/KAOS-1.7.0.jar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.7.0.tar -Algorithm SHA256
Get-FileHash build/distributions/KAOS-1.7.0.zip -Algorithm SHA256
git diff --check
```

Release preparation verifies the version, all 11 local verification tasks, the
complete deterministic test suite, all three rebuilt versioned artifacts,
changed local documentation links, release metadata, and whitespace.

## Publication procedure

1. Review and merge the `1.7.0` release checkpoint pull request.
2. Fast-forward local `main` to the exact merge commit.
3. Confirm merged `main` has the same tree as the validated preparation head.
4. Reuse validation only when those trees are identical; otherwise rerun it.
5. Create annotated tag `v1.7.0` with annotation
   `KAOS 1.7.0 - Multi-Tool Capability` at verified merged `main`.
6. Push only the `v1.7.0` tag.
7. Create the GitHub Release from that tag using the reviewed release notes.
8. Upload `KAOS-1.7.0.jar`, `KAOS-1.7.0.tar`, and `KAOS-1.7.0.zip`.
9. Verify local and remote tag targets, annotation, release assets and hashes,
   release metadata, Epic/Project state, milestone closure, branch cleanup,
   mirror synchronization, and clean synchronized `main`.

## Limitations and next checkpoint

This version identifies the complete bounded multi-tool capability. It does not
claim dynamic tool discovery, automatic advertisement, multiple calls per turn,
autonomous chaining or planning, browser automation, production readiness, or
permanent API compatibility.

Epic 009 and Feature 009.01 remain inactive until explicitly started.

# KAOS 1.4.0

## Status

`1.4.0` is the cumulative First Memory Capability release of KAOS. Its annotated
Git tag is `v1.4.0`, and its GitHub Release publishes the versioned JAR, TAR, and
ZIP produced from verified merged `main`.

This checkpoint represents every verified capability from the evolutionary
reset through completed Epic 006. It is not a claim of production readiness, a
stable public API, permanent SQLite compatibility, general-purpose memory, or
completion of the broader KAOS vision.

## Included prior capabilities

- one-goal-at-a-time development rooted at roadmap #814;
- one root Gradle/Java 21 application and one production entry point;
- bounded local Ollama prompt submission and persistent conversations; and
- a complete local Knowledge and RAG path with deterministic source citations.

These cumulative capabilities were previously checkpointed by `v1.3.0`.

## Included First Memory capability

- one explicit application-wide `answer-detail` preference;
- three structured values: `concise`, `balanced`, and `detailed`;
- create-only admission and version-1 local SQLite persistence;
- exact validated retrieval across process restarts;
- one fixed KAOS-owned instruction supplied only to one-shot `ollama-prompt`;
- explicit inspection, atomic editing, and explicit deletion;
- a content-free privacy report covering collection, storage, AI use, and
  presence; and
- deterministic lifecycle evaluation across commands, SQLite, application
  composition, real Ollama HTTP serialization, and loopback NDJSON.

## Run and verify

From the repository root with Java 21:

```powershell
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all
```

Run the complete memory lifecycle with a private local data directory:

```powershell
$env:KAOS_MEMORY_DATA_DIRECTORY = "D:\kaos-data"
./gradlew.bat --% run --args="memory-create answer-detail balanced"
./gradlew.bat run --args=memory-privacy
./gradlew.bat --% run --args="memory-inspect answer-detail"
./gradlew.bat --% run --args="memory-edit answer-detail detailed"
./gradlew.bat --% run --args="memory-delete answer-detail"
```

The release build produces `KAOS-1.4.0.jar`, `KAOS-1.4.0.tar`, and
`KAOS-1.4.0.zip` under `build/libs` and `build/distributions`.

## Security, privacy, and ownership

- Memory is collected only through explicit lifecycle commands.
- The structured value remains in the configured local `memory.db`.
- Only one-shot `ollama-prompt` can send its fixed instruction to loopback
  Ollama; conversation and knowledge paths do not consume it.
- The privacy report shows presence without the stored value.
- Storage and command failures remain content-free and non-destructive.
- No remote provider, telemetry, automatic extraction, free-form memory,
  credential store, plugin system, background worker, or separate runtime
  service is introduced.

## Compatibility and limitations

- Memory schema version 1 is validated but has no permanent migration promise.
- Filesystem access is governed by the local OS account and directory
  permissions; this release does not claim encryption or ACL management.
- There is one fixed preference, one local profile, and one one-shot AI consumer.
- Exact request construction is tested; model adherence and prose quality remain
  model-dependent.

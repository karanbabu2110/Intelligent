# KAOS 1.7.0

## Status

`1.7.0` is the cumulative Multi-Tool Capability release of KAOS. Its annotated
Git tag is `v1.7.0`, and its GitHub Release publishes the versioned JAR, TAR, and
ZIP produced from verified merged `main`.

This checkpoint represents every verified capability through completed Epic
008. It is not a claim of production readiness, stable public API, unrestricted
network or filesystem access, browser automation, autonomous planning, or a
plugin framework.

## Included capability

- the prior `read_local_file` and `http_get` paths;
- one bounded `web_search` tool through a configured SearXNG endpoint;
- one read-only `tools` catalog with privacy-safe configuration status;
- immutable shared tool descriptors and an insertion-ordered static registry;
- explicit operation-specific advertisement and at most one validated model
  tool call;
- a shared approval and execution lifecycle around existing concrete validators,
  approval objects, single-use grants, and executors;
- one no-tools model continuation after successful execution;
- bounded SQLite history containing only tool name, opaque operation UUID,
  decision, terminal outcome, and timestamps; and
- the Feature 008.08 evidence-backed decision to retain this small contract.

## Run and verify

```powershell
./gradlew.bat clean verifyLocal --no-daemon --warning-mode=all --console=plain
```

Inspect registered tools and local terminal history:

```powershell
./gradlew.bat run --args=tools
./gradlew.bat run --args=tool-history
```

The release build produces `KAOS-1.7.0.jar`, `KAOS-1.7.0.tar`, and
`KAOS-1.7.0.zip` under `build/libs` and `build/distributions`.

## Security, privacy, and ownership

- Registry membership and model selection never authorize execution.
- Each concrete tool validates its own resource and requires exact approval for
  one attempt.
- Denial, invalid input, end of input, interruption, and cancellation fail
  closed; failed execution does not retry and grant reuse is rejected.
- File content and external responses are supplied only to the configured local
  model continuation and are not written to tool history.
- History and diagnostics omit arguments, targets, prompts, configuration,
  content, and external response bodies.
- The catalog and history views are read-only and do not contact tool targets.

## Compatibility and limitations

Stable command names, environment variables, configuration, and tool names are
unchanged. Tool composition is static and local. Callers explicitly choose the
allowed set, and successful continuation advertises no tools. KAOS does not
provide dynamic discovery, automatic advertisement, multiple tool calls,
chaining, planning, retries, fallbacks, browser rendering, or remote history.

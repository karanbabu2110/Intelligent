# Structured Agent Planning

Feature [009.11](https://github.com/karanbabu2110/KAOS/issues/1093) makes the
existing bounded plan contract explicit at the Ollama request boundary. Prompt
text still explains how to choose evidence, while Ollama's `format` field now
contains a JSON Schema generated by `AgentPlanFormat`.

The schema permits only the four implemented plan shapes:

- stable knowledge followed by synthesis;
- one `read_local_file` followed by synthesis;
- one `web_search` followed by synthesis; or
- `read_local_file`, then `web_search`, then synthesis.

The planning instruction gives `web_search` two reasons: freshness can
materially affect the answer, or the model's internal knowledge is insufficient,
uncertain, incomplete, obscure, or unlikely to answer reliably. It reserves
`STABLE_INTERNAL` for sufficient and reasonably stable knowledge, directs the
model not to invent missing information, and selects `MIXED_EVIDENCE` when a
local dependency accompanies either public-evidence reason. Only the evidence
shape is returned; no reasoning trace or confidence percentage is requested.

It reuses the exact Epic 008 file-path and search-query argument schemas. When
`FreshnessPolicy` classifies a goal as `REQUIRED`, the generation schema omits
the two shapes without search. A similarly narrow `LocalEvidencePolicy`
requires a local-containing shape when a goal explicitly asks KAOS to read or
compare repository evidence. When both requirements apply, only the mixed
three-step shape is generatable. When the goal contains one explicit supported
relative file path, the schema preserves that exact path and Java verifies it
again. The path-free phrases `agent architecture`/`agent design`/`agent
boundaries` and `tool architecture`/`tool design`/`tool boundaries` map only to
their existing package summaries. No filesystem discovery or general retrieval
is implied. These constraints guide generation but grant no authority:
`AgentPlanner` still parses and validates the returned JSON, resolves tools
through the existing registry and allowlist, and rejects any violation before
execution or approval.

`FreshnessPolicy` remains a separate deterministic safety guard for obvious
recency cases. A model-selected knowledge-gap search does not require or create
a Java knowledge classifier: when freshness is `NOT_REQUIRED`, the schema still
allows `CURRENT_PUBLIC_EVIDENCE`, and the ordinary strict planner accepts that
shape. Conversely, a model cannot use `STABLE_INTERNAL` to bypass a
deterministic `REQUIRED` freshness assessment.

## Safe diagnostics

Every planner rejection retains its existing stable error code and now carries
a reason-specific, content-free explanation. Messages distinguish malformed
JSON, evidence-shape mismatch, step and tool limits, unknown or disallowed
tools, malformed arguments, invalid ordering, and missing required freshness.
Each explanation states that no tool ran. KAOS never prints the raw model
response, goal, file path, query, prompt, or provider internals.

Preparation also preserves the Epic 008 whole-file limit. An oversized local
target reports `LOCAL_FILE_TOO_LARGE` and the 2,048-byte boundary before
approval, without printing its path or reading any content.

Provider failures preserve the safe `KAOS-AGENT-MODEL-PLANNING` code while
identifying whether Ollama was unreachable, returned an invalid response,
reached a token or local bound, lost its stream, timed out, or was interrupted.
Approved SearXNG failures retain distinct agent reasons for an unreachable
service, timeout, invalid JSON response, and an oversized bounded result. The
messages provide recovery at the failed boundary without printing the goal,
model output, approved query, configured endpoint, response, or exception.

## Preserved failure boundary

Structured generation does not relax validation and does not introduce output
repair. A rejected response stops the run. KAOS does not retry, ask another
model, replan, select a fallback tool, or execute a partial proposal. Tool
approval remains a later, independent Epic 008 boundary.

## Known limitation

JSON Schema constrains syntax and the available bounded shapes; it cannot make
a small model choose the best local file or search wording. The local policy is
deliberately narrow phrase matching rather than general language understanding.
Knowledge insufficiency is deliberately model-driven, so a model may still
under-search or over-search. The user sees and independently approves the exact
query before execution.
Exact requests are
still shown to the user before approval, and invalid or unavailable resources
still fail safely without retry.

## Verification

The forced focused selection executed 136 agent, Ollama-boundary, application,
and routing tests with zero failures, errors, or skips. The clean repository
checkpoint executed all 11 `verifyLocal` tasks and 540 tests across 72 suites:
536 passed, zero failed or errored, and four existing platform-specific symlink
scenarios were skipped.

The knowledge-gap scenario deterministically classifies an obscure public
information goal as freshness `NOT_REQUIRED`, supplies a model proposal for
`CURRENT_PUBLIC_EVIDENCE`, executes one approved local-fixture search, and
synthesizes only from the returned evidence. Existing scenarios still prove a
stable concept uses no tool, explicit currentness requires search, local-only
uses one file, mixed evidence preserves file-then-search order, required
freshness rejects `STABLE_INTERNAL`, and an empty search stops without fallback.

Live local checks used installed `qwen3:4b-instruct`, the real repository read
root, and configured SearXNG. The original `README.md` goal no longer failed as
a malformed plan; it stopped before approval with `LOCAL_FILE_TOO_LARGE` because
the 28,830-byte file exceeds the preserved 2,048-byte limit. The path-free tool
architecture goal resolved to the 381-byte tool package summary, produced the
exact file approval prompt, and retained required current-public verification.
The approval was denied, proving the checkpoint without reading the file or
sending a search query.

The same mixed goal was also exercised with installed `qwen3.5:4b`. It produced
the constrained mixed plan and reached the exact 381-byte file checkpoint; the
approval was denied, so no file or public query was sent. A separately approved
manual run preserved the completed local evidence when SearXNG was unreachable.
The result now reports `SEARCH_SERVICE_UNAVAILABLE` and directs the operator to
start or verify the separate service; it does not expose the endpoint and does
not retry.
